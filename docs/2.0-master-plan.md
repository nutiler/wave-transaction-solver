# Wave Solver 2.0 master plan

Proposed scope agreed during the 0.5 → 1.0 retrospective. This document authorizes no live financial changes. The adjacent [master prompt](2.0-master-prompt.md) is a portable implementation handoff; private identifiers must be supplied locally.

## Purpose

Keep Wave books complete, explain transactions using evidence, prepare specific changes for review, and prove approved changes worked. Preserve the useful learning from the prototype while building a fresh application.

## Responsibilities

| Component | Job |
|---|---|
| Extension | Collect files and live information; execute approved supported operations; capture results |
| Local processing | Parse, normalize, compare, calculate, validate, and checkpoint |
| ChatGPT/Codex | Investigate ambiguity, interpret evidence, explain and propose changes |
| User | Confirm purpose, supply evidence, approve or reject actions and rules |
| Wave | Maintain accounting records |

## Workflow

1. **Account inventory and master history.** Maintain stable account identities, currencies, mappings, import methods, closed-account history, statement coverage, and one master transaction history with source provenance. Preserve exact IDs as strings, transaction/clearing dates, original descriptions, source occurrence counts, splits, reviewed status, and observed relationships.
2. **Collection and coverage.** Collect Wave, Apple Card, Amazon, PayPal, Venmo profiles, and supporting statements. Distinguish downloaded, imported, verified, confirmed no activity, unavailable, incomplete current periods, and manual completion. Preserve originals and dated snapshots.
3. **Safe Apple imports.** Compare against the exact Wave card account; prepare a missing-only CSV with an exclusion report. Handle date conventions, refunds, backfilled rows, and repeated legitimate purchases. Verify the import before another attempt.
4. **Explanations and evidence.** Enrich generic processor/retailer descriptions from orders, items, recipients, notes, and refunds. Preserve original text and useful user edits. Confirm service and purchaser identity rather than inferring from amounts alone.
5. **Manual check/cash/deposit review.** Attach images, checkbook entries, deposit records, receipts, and explanations to existing transactions. Support grouped deposits and partial payments without fabricating duplicates.
6. **Duplicate investigation.** Separate repeated imports from cross-account money movements. Match using direction, account, date, currency, references, evidence, existing relationships, and occurrence counts. Show which record survives any proposed deletion.
7. **Transfers and fees.** Preserve actual purchases while connecting funding and cash-outs. Verify both transfer records and their relationship. Support explicitly approved staged replacement of incorrect links. Split supported gross/net fees; never invent balancing adjustments.
8. **Categorization and learning.** Normalize merchant aliases separately from financial treatment. Use items, business purpose, account, purchaser, and confirmed decisions. Historical categories and Wave AI are evidence, not automatic rules. Ask for confirmation of reusable rule scopes.
9. **Reviewable plan contract.** Versioned constrained actions carry IDs, source snapshots, before/after values, evidence, effects, dependencies, approval, attempts, and postconditions. Material revisions invalidate approval. Unsupported or stale plans fail specifically.
10. **Execution and recovery.** Use one business-scoped executor lock, persistent per-stage checkpoints, exact-record preflight, bounded targeted reads, and save-outcome recovery. Never automatically repeat uncertain writes. Continue independent approved work and hold dependent work. Adopt proven manual results.
11. **Reconciliation and loans.** Compare dated account balances with statements after coverage and repairs. Recheck after balance-affecting changes. Maintain lender evidence and approved treatment per loan, avoid duplicate interest, distinguish paid/accrued amounts, and keep unsupported annual entries pending.
12. **Regular interface.** Collect → check coverage → prepare plan → review → apply → verify. Show freshness, gaps, focused questions, approvals, verified actions, remaining actions, and exact blockers. Preserve the full-width Wave layout enhancement.
13. **Year-end handoff.** Assemble coverage, reconciliation, evidence, supported annual adjustments, and unresolved tax questions. Entity type and accounting method are setup facts. Do not imply bank records establish all tax obligations.
14. **Scheduling and migration.** Prove the manual loop first; then verify collector invocation, login handling, files, completion, and analysis handoff. Scheduled collection/planning does not authorize scheduled writes. Retire the legacy interface only after acceptance while preserving recoverable source and private evidence.

## Acceptance gates

| Gate | Required evidence |
|---|---|
| Collection | Accurate coverage, preserved originals, recognized manual work |
| Planning | Exact records, resolved evidence references, valid calculations and dependencies |
| Execution | Supported real Wave operations with defined postconditions |
| Recovery | Safe interruption/resume without duplicate writes; manual outcomes recognized |
| Completion | Fresh-export agreement and relevant statement comparisons |

Prove the difficult browser interactions early. Distinguish fixture tests, controlled-browser tests, observed live operations, fresh-export checks, and statement checks. Do not manufacture financial changes to obtain a test case.

## Keep and leave behind

Keep evidence, confirmed decisions, source knowledge, precise links, reliable collection methods, checkpoints, and honest diagnostics. Leave behind overlapping tools, repeated full-history scans during repairs, hidden blockers, misleading progress, and promises based only on simulations.

No cloud backend or embedded AI API is required for the first manual file-based handoff. Use relevant evidence subsets, exact local arithmetic, recoverable Windows persistence, and clear separation of private data from public code.
